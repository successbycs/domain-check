# Documentation guide

Start here when you need to find project information.

| File or folder | What it contains |
| --- | --- |
| [project-context.md](project-context.md) | Why we are building the project, its scope, and what is out of scope. |
| [decisions.md](decisions.md) | Decisions that have been agreed and the reason for each one. |
| [architecture.md](architecture.md) | How the PoC will run and the responsibility of each planned part. |
| [report-schema.md](report-schema.md) | The planned report fields, output formats, caveats, and scoring rules. |
| [backlog.md](backlog.md) | The next pieces of work and questions that still need an answer. |
| [communication-style.md](communication-style.md) | The plain-language, beginner-focused communication agreement. |
| [development-workflow.md](development-workflow.md) | How we discuss, explain, test, and promote agreed decisions. |
| [learning-log.md](learning-log.md) | Short notes on what we have learned while building. |
| [Feedback/](Feedback/) | Conversation and review records. These are useful history, not the final source of truth. |

## How we keep documentation current

1. Discuss an idea in a feedback document or conversation.
2. Confirm the decision.
3. Add the agreed result to the relevant document above.
4. Keep unfinished questions in `backlog.md`.
